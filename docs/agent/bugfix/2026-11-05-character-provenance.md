# 角色图片来源提交号与入库前校验

首轮生产候选在全量 SQLite 入库后的来源校验失败：`character has invalid or unpinned provenance`。注册表保持旧版本，候选没有发布，失败工作目录按既有规则清理。

部分试用/测试 Avatar 没有独立的 genshin-db 角色条目，但共用正式角色图标，仍能匹配该仓库的立绘映射。原逻辑从角色自身来源列表推断图片映射的提交号；没有匹配时退回固定的旧提交 `49a6544...`。首轮补充源实际是 `8e5badd...`，所以正确的最终校验拒绝了不一致来源。本地预览使用旧提交，因而没有暴露这类偏差；预览里有 32 个本地化记录只有图片映射来源。

修复由媒体 CLI 将已验证的 `supplementCommit` 显式传入图片映射处理，不再从角色资料推断或使用旧值。普通映射缺少有效提交号时立即失败；显式外部映射仍使用其独立的固定哈希和提交校验。

全量构建在数据库导入前检查每条角色结构及全部嵌套来源，并在错误中记录 Avatar ID。入库后仍保留相同的来源、摘要、覆盖率和文献链接验证，没有放宽任何发布条件。

验证：针对性 38 项通过；完整知识服务 251 通过 / 7 个可选 PostgreSQL 跳过，发布控制器 31 通过。证据位于 `artifacts/characters/provenance-fix-*.log`。最终 CI 和重新发布结果见角色发布记录。
