# Brand favicon and Apple touch icon

## 1. Background & Problem

The site had no favicon metadata or browser icon. The user requested an icon and direct production deployment.

## 2. Root Cause / Approach

The existing `Emblem` in `components/ui.tsx` is native SVG. Simplify its leaf and diamond geometry for small sizes rather than generating a separate bitmap identity. Use a dark blue tile with cream and gold marks for contrast in both light and dark browser chrome.

## 3. Key Changes

- `apps/web/src/app/icon.svg` is the editable source. Next.js file conventions emit a cache-versioned SVG icon link without manual layout metadata.
- `favicon.ico` contains native 16, 32 and 48px PNG entries for browser compatibility; `apple-icon.png` is an opaque 180px PNG so iOS controls its own corner mask.
- Regenerate both raster assets with `node scripts/generate-icons.mjs`. The script uses the sharp dependency declared by the installed Next.js package.

## 4. Conclusions / Lessons

Local production build and TypeScript checks passed. Browser checks confirmed all three icon declarations, MIME types, sizes, and exact file bytes; ICO entries were checked at 16/32/48px. Light/dark small-size previews and the homepage screenshot were visually inspected. No model request was sent.

Deployment uses the existing web-only Compose flow, with a candidate and rollback image. Runtime receipts and screenshots are kept under ignored `artifacts/deploy/favicon-20261103/`; compare production icon hashes with the reviewed source files after deployment. Knowledge data and infrastructure configuration are outside this change.
