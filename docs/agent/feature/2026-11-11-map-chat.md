# 主站 Agent 地图查询与聊天卡片

用户在完成原型、原始围栏和对话内地图演示后，明确要求把地图查询与卡片协议接入虚空终端。实现位于当前 `codex/map-chat` 分支，保留既有原型/研究文档；没有提交、推送或部署。

## 实现

- `server/map-data.ts` 读取可复现的不可变地图快照；准备脚本 `scripts/prepare-map-data.py` 核验输入、补充有来源的英文名称、复制瓦片/图标、哈希内容寻址。运行期不启动 Python。
- `server/maps.ts` 和 `map-spatial.ts` 提供地区检索、精确资源统计、父区平面约束、子区已知高度、多片并集、交集边界距离及同级重叠检查。3D crosscheck 优先，其他点用国家校准矩阵。缺围栏、父区、锚点或独立场景校准都返回限制，不能伪造零。
- `/api/maps/regions`、`/api/maps/query` 为只读接口。图片接口校验路径、快照索引、SHA-256、大小和 MIME；缺片只允许固定 AppSample 7.2 路径，限时、限并发。瓦片不反复读取整份点库。
- `map-research.ts` 注册 `search_map_regions` / `query_map_resources`，通过地区/资源目录识别自然语言；地图问题不因原文无命中提前结束。最近用户轮分别提供缺省地区/资源，不把旧回答当证据。结构化卡片仅由服务端查询生成，模型上下文只包含受限摘要。
- `map-cards.ts` 定义 schemaVersion 1 的 `resource-map`，4 卡/500 点上限、有效数字、固定资产路径、受限来源 URL。`parentPolygons` 与 `polygons` 的交集是有效平面范围，截断只影响展示。
- `maps` SSE 事件与 `done.maps`、独立的 `mapSnapshotId` 贯穿请求校验、Terminal、IndexedDB、分支和 Markdown 导出。旧消息兼容，未知版本/恶意字段被过滤。原文 `snapshotId` 和图鉴 `cards` 不变。
- `resource-map-card.tsx` 使用 Canvas 高清瓦片、原图标、父子交集阴影/描边、按角色聚合、点选、拖拽、滚轮、手机双指与键盘操作；分页标点列表提供可访问入口。同内容的新 SSE 对象不重置选点/缩放。图片并发、缓存和销毁均有界。

完整使用与协议见 [docs/map-chat.md](../../map-chat.md)。Compose 新增地图目录只读挂载；本地默认 `data/maps`，可设绝对路径 `MAP_DATA_DIR`。

## 审查与验收

独立审查发现并修复：多轮地区指代回退过早、普通“找/标出”请求未进地图工具、SSE 新对象重置 Canvas、显示子区原始围栏与父子交集统计不符、父边界误差漏报。聚焦复审确认全部闭环，55 项相关测试通过；额外 6,500 个随机几何距离比较最大误差约 3.3e-13，416 个真实区域边界计算合计约 258 ms。

最终 Web 单测 30 文件、552 项通过；类型检查、生产构建、diff check 通过。Canvas 单元/像素检查覆盖父子交集、反向 ring、多片内部缝、空交集、DPR2，以及同内容替换/追加卡片时保持交互。浏览器还发现键盘焦点 Canvas 层级遮挡按钮，已提升控制层并增加回归。连续缩放后的早期截图仅完成 6 块瓦片，真实 fetch/decode 结清后为 39 块且空白消失；加载状态现按实际可见队列判定，E2E 断言 pending/failed/active 均为 0 后截图，新增 5 个状态回归用例。

最终地图 E2E 桌面/手机深色 2/2 通过（可见瓦片队列实际完成后复跑 13.7s），覆盖真实 API 两点、原始瓦片、键盘、拖拽、双指缩放、点位来源、text_delta/done 后状态保持、刷新历史、独立地图版本追问。图鉴卡片桌面/手机回归也已通过。证据留存 `artifacts/map-chat/desktop.png`、`mobile.png`、`ormos-card.json`、`acceptance.json`。地图浏览器使用真实 API/瓦片与受控 SSE 流；DSH 测试使用真实执行器、真实查询与受控模型返回。本机没有配置模型密钥，不能将这些测试称为真实模型连通验收。

Compose 的只读地图挂载已配置；本机无 Docker CLI，未进行容器构建/运行验收。

本地体验使用生产模式 `http://127.0.0.1:3000`；BYOK Key 仅内存保存，刷新后需重输。开发模式检查遇到 Next 快速刷新循环，生产模式已避开；没有修改开发服务器配置或声称已解决该独立环境问题。
