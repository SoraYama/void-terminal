# 地图数据能否供问答 Agent 统计区域资源

用户询问当前地图标点是否已经可被 agent 索引，并举例「须弥的奥摩斯港有多少草神瞳」。本次只检查现有代码和固定源数据，没有新增接口或接入生产。

后续[小区域围栏核验](2026-11-10-map-geofences.md)已完成官方 7.2 原始资源获取、583 个区域围栏、坐标校准和本地查询验收。`prototypes/world-map/region_query.py` 已实际回答奥摩斯港 2 个草神瞳（33876、33877），并有可缩放核验图。下文记录此前的站内 Agent 状态；**本地查询已可用，线上 Agent 仍未注册地图查询工具**。

## 已确认的状态

- 地图的 89,091 条点位由 `prototypes/world-map/build.py` 解码后嵌入本地 HTML 的 `atlas-data`，浏览器 `atlas.js` 直接读取、筛选和聚合。开发环境可用脚本读出这些结构化记录，但产品问答服务尚未连接此数据集。
- `apps/web/src/lib/server/research.ts:122` 起的 Agent 工具只有 `search_corpus`、`find_documents`、`read_source`、`read_document`，分别用于知识语料检索和原文读取。`agent.ts` 从 `prepareResearch()` 取得这些工具，没有区域解析、地图查询或空间统计工具。
- 固定 `markers.json` 的列为 `id,type,mid,level,lng,lat,meta`。当前主图有 271 条 `o403` 草神瞳。地图元数据 `areas` 仅有 `id,icon,center,zoom`，七个国家级相机定位项没有区域多边形，也没有奥摩斯港条目；原始点位 meta 未发现 Ormos / 奥摩斯港归属。
- 地图上点击「须弥」目前是按源相机中心定位，不表示所有点已经有须弥或港区的空间归属。文献中出现地名也不能替代地名到地图边界的关系。

## 对示例问题的结论

当前站内 Agent 不能基于这批点位可靠计算「奥摩斯港有多少草神瞳」。需要同时补齐地图工具接入和地理范围定义。即使把全部记录接进检索，也不能由坐标自行推出港区边界；港区本体、周边山地和地下是否纳入会影响结果。

建议后续闭环：

1. 结构化地图快照入库，保留来源、版本、地图、资源类型、坐标、楼层与稳定点位 ID。
2. 地名索引提供别名及父子层级，例如须弥 / 阿陀河谷 / 奥摩斯港；统计范围需要有来源可核验的多边形或明确标为产品约定的边界，不能偷偷用任意半径代替。
3. Agent 先解析地区和资源，再调用确定性的空间统计，结果同时返回计数、所用范围、点位 ID、楼层信息和快照版本，支持在地图上高亮复核。没有明确楼层的记录单列为楼层未标注，不自动计为地表。

这一轮没有把示例的港区数量猜成一个数字，也没有把开发脚本可读误报为线上 Agent 已接入。
