# 地图放大发糊：原始瓦片清晰度对比与在线高清

后续界面已按[六条浏览器批注](../optimize/2026-11-10-map-ui.md)移除高清开关和状态文案，两种文件名均默认高清。下文保留最初高清接入的原因、来源对比和当时验收记录。

用户反馈 7.2 Canvas 原型放大后模糊，要求搜索更清晰的版本。读取现有构建和绘制逻辑，再对 AppSample 和官方底图做同位置实图比较。

## 原因与来源

- 上一版为控制离线体积，全图仅打包 10–12 级，枫丹局部 13–14、旧日之海与冰神瞳区域 13；继续放大时拉伸旧图。此外选瓦片时忽略 devicePixelRatio，Retina 使用了偏低一级的图。
- [AppSample 当前地图](https://genshin-impact-map.appsample.com/)公开配置：提瓦特原生瓦片最高 15（地图交互 maxZoom=16 不代表有 16 级图片）。[实际 15 级样本](https://game-cdn.appsample.com/gim/map-teyvat/v72-rc1/15/tile-14_29.jpg) HTTP 200、256×256 JPEG、CORS `*`。同位置 12/14/15 级原图均读取并比较。12→15 同范围采样密度每边增加 8 倍，但不能说视觉细节提高 8 倍；14→15 在这块区域提升有限。
- 其他场景原生上限：旧日之海、渊下宫、层岩巨渊、空之神殿 13；霜月 14；远古圣山 12。褪色古堡 B1–B4 是 overlay PNG，没有更高层级瓦片配置。
- [官方公开配置](https://waf-api-takumi.mihoyo.com/common/map_user/ys_obc/v3/map/info?map_id=2&app_sn=ys_obc&lang=zh-cn)本次返回 `map_version=bd70cde160dbd523926208d9fa8961a1`、`total_size=[36864,32768]`、`origin=[24207,16411]`、zoom -4..0。取最高精度 P0 的 `77_58`、`78_58` 两张图，与 AppSample 枫丹湖光铃兰 #56744 附近作相同范围比较。沿用之前枫丹局部仿射并更新 origin；对比区域约为官方图 128×128 像素，AppSample 15 级为 256×256。该样本官方图没有更清晰，不推论为全图每个区域都较差。
- [kxxoling 快照元数据](https://raw.githubusercontent.com/kxxoling/genshin-map-data/main/data/teyvat/meta.json)本次仍标注 7.1.0，与当前官方配置不是同一地图版本；不能当作当前 7.2 替换来源。[空荧酒馆](https://yuanshen.site/docs/)查到分层等能力，但未取得可证明精度高于 AppSample 的同位置样本，不将其列为已验证的高清替代。

## 改动

`prototypes/world-map/build.py --online-hd` 新增独立高清 HTML，嵌入每个场景的固定版本瓦片 URL、层级与网格范围。旧的离线交付文件保留。

`atlas.js` 按 `ceil(log2(scale × DPR × 360 / 256))` 选择层级；原有离线金字塔先铺底，再请求当前视野缺少的高清瓦片。源 Y 网格向北增长，Canvas 行号为 `-sourceY-1`，沿用已验证坐标。最多 6 个并发，12 秒超时，离开视野取消请求，256 张位图缓存；超大画布降一级以维持缓存预算。加载失败保持离线地图，开关可重试。未在线批量下载全世界。

新增「在线高清」开关与加载/回退/原图精度提示。楼层沿用原始 PNG，明确提示精度上限，不用生成或锐化图冒充地图数据。

## 验收

- `verify-hd.cjs` 实际从 Chromium 加载 15 级 CDN，验证 `tile-14_29.jpg` HTTP 200、视野内所需高清图全部就绪；相同 CSS 缩放下 DPR 1→2 选择 13→14 级。
- 拦截 CDN 模拟失败，仍有离线瓦片、回退提示；关闭在线高清后无待加载请求，缓存符合上限；无页面脚本错误。
- `verify.cjs` 在高清文件关闭在线模式后通过：7 场景、230 冰神瞳、枫丹分类搜索、古堡四层与入口、旧日之海分层、桌面拖动缩放、手机双指缩放。
- 已目视检查同区域三档瓦片和官方 P0 四图对比、DPR 2 枫丹近景、手机古堡控件布局。
