# 对话内地图展示与站内 Agent 接入状态

早先用户询问对话内展示能力时生成了交互示例；随后用户明确要求“接一下吧，地图查询和卡片协议都搞好”，已在同日接入主站。当前实现与验收记录见 [地图 Agent 接入](../feature/2026-11-11-map-chat.md)。以下保留早先示例的范围与证据。

## 接入前的主站状态

- `apps/web/src/lib/server/research.ts` 仍只有 `search_corpus`、`find_documents`、`read_source`、`read_document` 四个文本工具，没有地图区域查询工具。
- `apps/web/src/lib/answer-cards.ts` 的消息卡类型仅为 `character | weapon | artifact`。
- `apps/web/src/components/answer-markdown.tsx` 对应渲染以上卡片，没有地图消息渲染器；Markdown 图片也被禁用。不能把本地地图和索引已就绪说成主站 Agent 已支持地图回答。

## 本次对话内示例

交付目录 `/Users/sorayama/.codex/visualizations/2026/11/09/01a1c014-f8de-7cb2-ab48-460de462f5ee/ormos-chat-map.html` 是 visualize 对话片段，603,625 字节，不依赖本地预览服务器或在线地图请求。包含 72 张已留存高清瓦片、游戏资源图标、奥摩斯港原生多边形，以及四个三维坐标交叉核验点位。

再次实际调用 `region_query.query`：计入 33876、33877，界外 33859、33860，数量 2、状态 crosschecked。为保持与严格边界的包含关系一致，本示例标点以已核验三维 XZ 通过须弥校准投影绘制。

支持拖动、缩放、点选、原始标点链接和选中状态保存；所有数据内嵌，外部来源只在用户点击链接时打开。对话主内容只展示该次查询相关区域，未把 89,091 条全量点库塞入片段。

## 验收与范围

使用 visualize 的沙箱预览包装进行真实浏览器检查：72 瓦片载入、4 标点、2 个计入；区域内和界外选择正确；按钮缩放与拖动有效；390 宽视口无横向溢出；无 JS 错误。桌面截图实际查看，底图和围栏正常。证据为同目录 `ormos-chat-map-audit.json` 与桌面/手机 PNG。

这个示例本身仅证明 Codex 对话展示能力。之后主站已实现只读地图工具、结构化消息、Canvas 渲染及历史恢复，详情和验证范围以 feature/2026-11-11-map-chat.md 为准；未部署线上。
