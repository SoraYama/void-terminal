# Map chat implementation plan

> **For agentic workers:** Follow the task ownership below; use TDD. The user has authorized direct execution. Independent query and renderer tasks may run in parallel under dispatching-parallel-agents; do not revert other work.

**Goal:** Deliver deterministic map queries and versioned interactive map cards in the existing Agent chat, including history restoration.
**Architecture:** Independent immutable map snapshots, typed server-only queries, bounded validated SSE map cards, React Canvas renderer. Corpus snapshot identity remains separate.
**Tech Stack:** Next.js 16.4.3, React 19, TypeScript, zod 4, Python preparation script, Vitest, Playwright.
**Spec:** `docs/superpowers/specs/2026-11-11-map-chat-design.md`

## Global constraints

- Map protocol: schemaVersion 1, kind resource-map, maximum 4 cards and 500 markers per card; custom AppSample projection only.
- Preserve missing-boundary, missing-height, overlapping-region and coordinate-calibration qualifications; never silently return zero for unsupported scope.
- `mapSnapshotId` is distinct from corpus `snapshotId`; immutable historical versions never fall through to latest.
- No model-generated HTML, arbitrary tile/image URLs, path traversal, or full dataset in model context.
- Preserve existing uncommitted work. Use current workspace on `codex/map-chat`; no push/deploy. Persistent data belongs in ignored `data/maps`.

## Review focus

- Map-only questions with zero corpus evidence must still reach tools and answer.
- Unsupported scope/ambiguity cannot display a confident zero; capped markers cannot masquerade as complete coverage.
- SSE maps must survive reload, branching, export and independent corpus/map snapshot changes.
- Malformed persisted messages must not create arbitrary network fetches or crash rendering.
- Slow/failed tiles and unmount/theme/resize transitions cannot leave blank or leaking Canvas behavior.
