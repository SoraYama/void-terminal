# 道具博览馆与背包数据补全

日期：2026-11-03。状态：用户已确认，按此设计继续实现并更新线上数据。

## 意图与已确认的选择

用户要求将两个公开数据源更新到最新，将武器、圣遗物、任务物品及其他背包物品的数值、介绍和图片整理完整，并设计接近原神游戏内风格的道具博览馆。用户已选择「游戏背包式：网格浏览与右侧详情」。现有站点是 Next.js 网站和 Python knowledge 服务，使用中文、英文、不可变知识快照及 SQLite 生产部署。

这项工作同时交付可重复的数据更新流程和可浏览的页面。本文其余具体交互和实现边界是实施建议，供用户确认；不是用户已逐项指定的要求。

## 方案比较

1. **游戏背包式（用户选择）**：分类和稀有度道具网格，右侧固定详情。便于快速切换和比较道具，与游戏体验接近；需要独立的物品结构与响应式详情交互。
2. 列表百科式：搜索结果列表加独立详情页，适合长文阅读，但较少体现背包视觉。
3. 展厅式：大幅视觉陈列加专题入口，适合精选内容，但不适合数千条道具的日常查找。

## 成功标准与范围

- 主源从 `792978e5503ecfba73dcb3562ed44a0d35a2abe2` 更新到检查时最新的 `bd35e243fa436f141f015cf221a6e19d0c34b7ca`；补充源保持当前最新 `49a6544a6c6ae36089cb42fa591fc46f01de8bcf`，扩展图片、数值和曲线获取范围。
- 新快照必须完成下载校验、正文归一化、结构化物品生成、覆盖报告和代表性数值验证，再替换线上活动快照。
- 博览馆包含武器、圣遗物、材料、食物、任务物品、小道具和其他背包类别。材料继续覆盖经验材料、突破材料、消耗品、图纸等；其他类别包括风之翼、名片、书籍、家具、鱼饵等来源确有的物品。
- 同一原始道具只展示一次；补充源提供附加资料，不能形成两张重复卡片。圣遗物按套装和部位浏览，配置中的等级、星级重复变体归并到同一可识别部件；保留原始变体映射。
- 不把数据仓库配置条数称为玩家可获得道具总数。明确标记的测试、废弃、占位记录默认隐藏，可通过「包含内部记录」查看；没有发布状态证据的记录显示「收录于源数据」，不推测已实装或可获取。
- 已有考据、藏书阁、引用定位与旧会话保持可读；新增物品详情可关联原始文献并带入考据。

这次不制作个人背包、账号登录、抽卡、装备配队、伤害模拟或玩家圣遗物评分。图片是有出处的原始资源，不使用生成图充当真实道具图片。

## 页面与视觉

概念稿为 `docs/design/item-museum-concept.png`。它用于确认整体风格和布局；图中的道具图形、文字和数值属于生成的示意，最终页面使用校验后的真实资源与数据。实现保留现有须弥背景、品牌、日夜主题和侧栏行为。

桌面：在现有侧栏加入「道具博览馆」，主区域顶部为紧凑标题、搜索和筛选，下面为可横向滚动的分类栏。左侧自适应网格，右侧约 360–400px 的详情面板；两侧内容可独立滚动。宽屏每行约 5–7 张卡，卡片包含图片、名称和星级；不显示虚构的拥有数量。

详情上半部为名称、类别、星级及稀有度底色中的大图；下半部用「属性 / 培养 / 故事 / 来源」页签组织内容。当前类型无对应内容时隐藏该页签，避免大量空面板。长介绍保留段落。右上支持关闭详情。直接链接可恢复道具选择。

手机：分类栏横向滚动，网格默认三列；点卡片打开全屏详情层，返回后恢复原筛选与滚动位置。支持系统返回键、Escape、焦点恢复和安全区。较宽平板采用四列和可切换的详情层，避免挤压正文。

配色沿用站点的纸白、蓝灰和暖金。稀有度使用游戏式灰、绿、蓝、紫、金卡面；选中态同时使用边框和标识，不能只靠颜色。图标沿用现有图标体系；正文与控件维持清晰对比、44px 触控区域、可见键盘焦点和 reduced-motion。

## 浏览与交互

- 搜索名称、别名、简介；中文和英文按站点语言展示，保留可用于检索的原名。输入约 250ms 去抖，服务端分页，不把所有正文和图片一次加载到浏览器。
- 分类、星级、武器类型和排序使用明确控件，默认按稀有度再按 ID 稳定排序。只提供有数据支持的筛选；第一版不提供推测的地区或游戏版本筛选。
- 默认进入武器类别并选中首个真实记录，避免空白详情。筛选无结果时提供清除筛选按钮；加载时维持网格尺寸并显示骨架，失败时保留当前选择并提供重试。
- 使用 `/museum` 作为稳定入口，查询参数保存类别、搜索、星级、分页和选中 ID；可直接分享道具。保持聊天和藏书阁入口可达。
- 详情显示「查看原始文献」和「向终端询问此道具」；后者只传递道具名称、ID 和当前快照，不把未校验的任意 raw JSON 当成模型指令。

## 结构化数据

物品与文献分开建模，统一绑定不可变 snapshotId。详情至少包含稳定 ID、语言、名称、类别、子类别、星级、简介、故事、图像、来源、关联文献、原始配置 ID、字段覆盖和记录状态。每个来源保存仓库、固定提交、路径及定位；主源和补充源的冲突保留来源，不静默用旧值覆盖新值。

### 武器

从主源 Weapon、WeaponCurve、WeaponPromote、EquipAffix 关联等级、突破、初始和成长属性，补充材料、故事、图像和精炼参数。界面提供合法等级与突破阶段，正确区分突破前后；精炼显示 1–5 中实际存在的等级，固定或不适用的技能不能虚构精炼。属性显示基础攻击、副属性、技能名称与展开后的技能文本。 `{0}` 等模板变量必须被正确替换；无法展开的字段记录为未解析，不当作完整文本展示。

培养页显示逐阶段突破材料与数量，明确区分「本阶段」与「累计」；可关联的材料能够打开详情。不能把突破材料误称为包含所有强化经验的完整培养成本。

### 圣遗物

按套装与部位组织，包含星级、适用部位、套装效果、部件简介和故事。关联 ReliquaryLevel、ReliquaryMainProp、ReliquaryAffix 数据，展示所选星级、等级下合法主属性值、可能副属性及单次初始/强化档位。明确这些是词条规则和可能数值，不伪造一件具体掉落圣遗物的随机结果。单件套不会被标记为缺少其余四件。

### 任务物品及其他道具

展示来源中真实存在的说明、用途、获取途径、使用效果、配方、任务关联或家具舒适度/负荷。任务关联仅在配置关系可验证时呈现，不根据名字编造任务。没有战斗属性的物品显示相应的用途和资料，不展示空白攻击力等字段。食品效果尽可能从对应使用/效果配置解析，保留未解析关联以进入覆盖报告。

### 图片与缺失资料

优先使用补充源已有的官方图片 URL；主源图标标识通过实际可用的资源服务映射，并校验响应状态、类型与尺寸。图片记录包括资源标识、URL、供应方、检查结果。可批量校验并缓存校验清单；浏览器懒加载，仅对允许的 HTTPS 域名取图。失败时显示类型图标与「图片暂缺」，同时记录到覆盖报告。

覆盖报告按类别统计名称、简介、图片、适用数值、故事、关联资料，区分「完整 / 不适用 / 上游缺失 / 解析未完成 / 图片不可达」。不适用与上游缺失不能用虚构内容补齐。保留缺失 ID 清单以便后续增量补充；上线说明必须如实给出未解决的数量。

## 服务与发布约束

沿用 Next.js + Python + SQLite/PostgreSQL，不引入新的外部付费服务。增加分页物品列表与详情接口，返回有效快照、筛选计数和受控的结构化属性；复用现有服务端代理鉴权，不向浏览器暴露 knowledge token。

结构化物品作为快照的一部分构建，激活时与文献使用同一指针。旧快照无物品数据时返回明确的未构建状态，不与新快照混合。数据获取与构建是显式命令；页面请求不触发全量更新。主源固定提交、Git tree、TextMap 校验和以及补充下载清单同时更新。

生产发布前保留原 SQLite 数据与活动快照的可回退副本；用停止服务后的完整文件或 SQLite backup 导出，不复制活跃主文件而遗漏 WAL。新库完整性、覆盖、文献检索和物品详情通过验证后才切换。更新代码和数据后检查公开入口、手机/桌面、图片、数值、检索、流式聊天与历史引用。失败时恢复上一个代码版本和数据库。

操作记录给出固定提交、构建时间、快照 ID、道具覆盖报告和复现更新命令；未来同步依次执行核实上游、更新校验清单、下载、构建、检查、发布与验证，不用手工覆盖线上几个 JSON。

## 验收重点

1. 最新固定提交与真实下载标记一致，未完整获取的数据范围不能标成 full。
2. 护摩之杖等代表武器的 1/90 级、突破前后、副属性和精炼效果与源表一致；新增武器不因补充源较旧而丢失。
3. 五件套、单件套、不同星级与部位的圣遗物规则正确；无不存在的属性组合。
4. 任务物品、食物、小道具、图纸等可查找；测试/废弃物品状态清楚；缺失资料不伪造。
5. 图片覆盖逐项有证据，界面处理图片失败；加载和筛选不会下载整库。
6. 桌面、手机、键盘、暗色模式、空结果、网络失败和可分享的详情链接可用。
7. 本地与生产测试结果分开记录；旧引用和聊天能力无回归；有可执行的更新与回退说明。

## 留给实施者的选择

SQL 表和索引的具体形态、内部函数拆分、缓存布局、数值格式化、网格断点以及测试样本由实施者决定，只要满足上述来源、快照、性能和视觉约束。可优先复用主源表建立完整装备计算，补充源只补充资料；避免把补充源较早的装备数值当作最新主源的替代。
