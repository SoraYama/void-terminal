# 群星图鉴：游戏角色菜单式资料模块

日期：2026-11-05。状态：用户确认名称「群星图鉴」及本方案后已完成本地实现、真实数据验收和独立审查；尚未发布生产。最终证据与来源缺口见 [实施记录](../../agent/feature/2026-11-05-character-archive.md)。

## 意图与已明确的要求

用户要求补齐角色信息，包括角色立绘、头像、属性、数值、故事、语音、天赋、命座等，并按照游戏里的方式展示；模块名称交由助手建议。

中文名为用户确认的「群星图鉴」，英文为 Character Archive，与「万象集录」并列。群星呼应角色与命之座，图鉴明确这是查阅角色的入口。

这是角色数据、素材接入、快照服务与完整前端页面的项目级新增功能。保留 Next.js、Python knowledge 服务、SQLite/PostgreSQL、中文/英文、现有侧栏、主题和来源阅读方式。

## 实施前证据与缺口

以下保留实施前本地代码及已有下载文件的实测，用于解释设计起点；不代表当前实现状态、生产数据库或全量素材可用性：

- `terminal.tsx` 只有首页、对话、原文库与万象集录视图；`apps/web/src/app` 没有角色页或角色 API。
- `ingest/normalize.py` 将 Avatar、FetterStory、Fetters 分别归一化为角色、故事及语音文本，并为后两者记录角色关联；当前阅读组件消费文献，未形成角色聚合详情。
- 本地简体中文补充源有 124 个 characters 文件、109 个 voiceovers 文件。这些是源文件数，不能称为当前正式实装或完整收录的角色数。
- 角色文件含称号、元素、武器、生日、所属、配音演员及突破材料；语音文件有台词、资源标识与部分解锁条件，资源标识不是可播放的 URL。
- 主源已下载 Avatar、AvatarCurve、AvatarPromote、AvatarSkillDepot、AvatarSkill、AvatarTalent、ProudSkill、FetterInfo、FetterStory、Fetters、AvatarCostume 等表。数值和技能关系尚未聚合为角色契约；无文本 hash 的数值行不会被普通文献归一化保留下来。
- `source_plan.py` 当前补充范围只有五类正文与八个物品支持文件，没有角色图片、角色成长曲线、角色天赋和命座的专用支持文件。
- 已读取固定提交下的 [角色图像映射](https://raw.githubusercontent.com/theBowja/genshin-db/49a6544a6c6ae36089cb42fa591fc46f01de8bcf/src/data/image/characters.json)，其包含头像、侧头像、立绘资源标识和部分外链；尚未逐个验证资源。不得把映射存在当作图片全量可用。

## 方案比较与取舍

1. **游戏角色菜单式（推荐，符合用户指定）**：角色头像切换，中央立绘或命座区域，左侧分区，右侧详情；保留查资料所需的搜索与筛选。
2. 百科长页式：适合全文检索和连续阅读，但不能满足用户指定的游戏内展示方式，不作为实施方向。
3. 直接把角色塞进万象集录的道具网格：可以复用外壳，但角色资料、技能倍率、命座及语音的交互与物品明显不同，不采用。

展示方式已有明确要求，不再发起新的视觉风格选择。角色页沿用站点已有纸白、灰蓝、暖金与原神素材体系；页面内容区按角色元素切换柔和背景色，文字区保持可读。使用真实二维立绘，第一版不引入可旋转三维模型。这是助手提出的实现边界。

## 页面结构

独立入口 `/characters`。入口先显示角色头像图鉴，可搜索名称、按有可靠数据的元素/武器类型/星级/地区筛选。点选进入游戏式角色详情，保留当前筛选结果用于头像条前后切换。详情直链恢复角色、形态、页签与快照。

桌面角色详情：

- 顶部为返回图鉴、角色称号与名称、横向头像条；所有角色均是公开资料，不呈现虚构的已拥有或未拥有状态。
- 左侧功能顺序为「属性 / 命之座 / 天赋 / 资料 / 培养」。不加入空白的装备槽；武器和圣遗物可通过相关资料跳转万象集录。
- 属性页中央为透明原始立绘，右侧为元素、星级、等级/突破选择与属性面板。
- 命之座页中央切换为该角色有依据的命座图与节点，右侧显示选中节点说明。
- 天赋页显示真实图标及天赋列表，选择后展开对应说明、等级和数值。
- 资料页使用「简介 / 故事 / 语音」二级页签，长文阅读时收起大立绘，给正文留足宽度。
- 保留「查看原始文献」「向终端询问」；后者只准备带角色身份与快照的草稿，不自动发送。

手机上图鉴为紧凑头像网格，详情为独立全屏内容；头像条与分区横向滚动，立绘和属性纵向排列，资料页优先正文。系统返回恢复图鉴筛选与滚动位置。保证键盘焦点、触控目标、主题对比和 reduced-motion。

## 各分区的内容和行为

### 属性与形象

展示原始立绘、头像、称号、星级、元素、武器类型、所属、生日、命之座名称与配音信息。服装和旅行者元素形态只在稳定映射和素材存在时开放切换，不推导不存在的版本。

等级和突破阶段为联合选择器，选项来自实际数据，区分突破前后。默认建议选择源数据中最高合法等级与阶段，并明确是「角色基础属性」，不是玩家装备后的实际面板。计算生命、攻击、防御、突破属性及源数据有依据的固定基础属性；公式、曲线和突破加成来自同一固定版本。未知字段保持缺失，不能补 0 冒充实际值。

不模拟装备、队伍、命座触发或战斗增益；展示命座说明不自动改变基础属性。若未来需要配装或伤害模拟，单独定义需求。

### 天赋

按角色技能组关联普通攻击、元素战技、元素爆发及固有天赋，使用原始图标。展示完整说明、冷却、能量、每级倍率及条件。升级范围依角色和天赋的实际表定义；基础等级与来源明确的等级加成分开，不把表中存在的高等级一律认定为可手动升级。

参数模板保留变量含义、百分比和固定数值格式，不能将所有数字统一乘 100。普通攻击多段、长按/点按和多形态分别保留。无法解码的字段列入覆盖缺口，不能把未替换模板显示为完成数据。

### 命之座

按源数据顺序展示节点图标、名称、完整效果。普通角色通常为六个节点，但不能硬补缺失或不适用节点。只有获得可验证命座图或节点布局时才展示其真实连线；否则以有序节点列表呈现并说明图示暂缺，不能用任意星点声称还原了原始星座。

所有已收录节点均可查看，不模拟玩家解锁进度。旅行者按性别和元素技能组保留正确身份，不串用天赋与命座。

### 资料：简介、故事、语音

简介包含人物介绍、生日、所属、配音演员等原始字段。故事按游戏来源给出的顺序、标题与条件组织；有条件变体时保留分支，不静默拼接相互冲突文本。可查看全部已收录故事，展示游戏内解锁条件，不要求用户实际拥有角色或达到好感等级。

语音包含闲聊、天气、关于自己/其他角色、战斗等源数据能支持的分类，展示标题、台词、条件与配音语言。目标是实际播放原声，不以只有文本的按钮作为完成。

当前两源已确认的是台词和资源标识，音频媒体来源尚待勘验。实施的第一阶段必须先验证音频来源、角色/台词/语言精确映射、浏览器可播放性及资源使用条件；选择结果和版本固定到素材清单。只开放有真实音频的语言，不把界面语言直接等同于配音语言。音频按点击加载，同一时间播放一条，切换角色/台词或离开页面时停止，不自动播放。

若无法找到可稳定使用的音频来源，应提交明确缺口和可行替代方案供用户决定；不能自行缩减为「台词版」并宣称需求完成。单条缺失可显示「音频暂缺」，但全量音频未接入属于整体未完成。

### 培养及关联

展示突破阶段材料、摩拉、天赋升级材料与可计算的本阶段/累计数量；材料可以精确 ID 跳转万象集录，并保持快照。未覆盖角色升级经验时，标题明确为「突破材料」而非「完整养成成本」。

名片、特色料理、服装等额外资料只在存在可验证 ID 关系时显示；不能按名字近似匹配生成关联。

## 数据、接口与快照

- 新增独立角色目录模型，文献、物品与角色均绑定同一个不可变 snapshotId。角色身份基于 Avatar ID，形态另用技能组等可证明的原始 ID 标识。
- 每个字段保留来源提交、路径和定位；主源数值优先，补充源用于补齐映射与可读资料，旧补充源不能静默覆盖较新主源值。
- 扩充现有源计划及 Git blob 校验范围。当前固定提交可作为开发基线；生产实施时读取实际候选清单，不把本草案中的提交当作届时最新状态。
- 建议增加 `/v1/characters`、`/v1/characters/{id}`、`/v1/characters/coverage` 和 Next.js 代理。列表分页，只载入轻量头像信息；故事、语音清单、倍率和大图按需加载。
- 角色构建必须参与候选完整性、摘要和覆盖校验，扩展现有刷新流程并保持单写者、候选验证、原子发布与恢复约束。页面访问不触发抓取或更新。
- 旧快照没有角色目录时返回明确未构建状态；旧物品、文献与历史引用继续可读，不把不同快照数据混合进角色详情。
- 隐藏/测试记录依据已有明确证据分类；公开源存在不等于正式可获取，无法证明发布状态时不作已实装承诺。
- 图像和音频保留源标识、实际 URL、校验状态、内容身份及对应角色/语言，不用生成素材替换真实角色。外部媒体按已验证域名和路径限制加载，失败时保留文本与重试能力。

## 验收与实施顺序

1. 先做素材和数据贯通：普通角色、旅行者形态、低星/特殊角色、缺失素材角色各取代表；确认立绘、头像、至少一条原声音频、基础属性、天赋、命座和故事真实可取得。
2. 验证全量源身份映射，输出按角色/语言/字段统计的覆盖报告，区分完整、不适用、上游缺失、未解析与不可达，不用源文件数充当完整角色数。
3. 完成角色聚合、存储/API、快照构建，再接游戏式图鉴和详情；保留原文阅读与询问草稿。
4. 数值回归覆盖 1 级、最高合法等级、突破前后；天赋至少覆盖多段倍率、固定值与百分比；旅行者切换不得串用角色技能。
5. 语音在真实浏览器播放、切换、暂停、失败恢复；有文本却无可播放音频不能通过音频验收。
6. 真实桌面/手机检查头像切换、详情直链、故事阅读、命座选择、等级控制、返回恢复、键盘、主题、加载及失败状态。
7. 检查物品、聊天、检索和旧引用无回归。构建及发布沿用现有候选验证和回退机制；本次设计草案不代表生产部署已获单独确认或已执行。

具体表结构、组件拆分、样式断点和缓存方式由实施者决定。功能范围不以单个样本页面代替；最终交付必须报告尚未解决的资源或字段缺口。
