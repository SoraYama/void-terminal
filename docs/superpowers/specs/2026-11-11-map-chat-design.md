# 地图查询与回答卡片接入

## 已授权目标

用户已确认接入地图查询和卡片协议，并要求直接推进。复用已验收的 7.2 数据与 Canvas 交互，使站内 Agent 可查询小区域资源、在回答中展示地图与真实标点、刷新后恢复卡片。沿用现有中英文、主题和用户隔离历史。只做本地实现与验收，本轮不发布。

## 实现选择

采用 Next.js 服务端只读地图快照 + 确定性 TypeScript 空间查询 + 结构化地图消息。它与现有文献快照分别固定：`mapSnapshotId` 不得冒充知识库 `snapshotId`。复用原始数据与校准规则，避免运行时 Python 子进程或将整页 HTML 作为模型输出。复用 iframe 原型会把查询、版本与消息历史割裂；引入 GIS 数据库对当前规模无必要。以上为执行选择，无额外产品范围。

## 协议

`MapCard` schemaVersion=1，kind=resource-map。携带卡片 ID、地图快照 ID/游戏版本/源时间、地区 ID/名称/父区/国家、资源 ID/名称、count/status/review、坐标系、地图瓦片配置、边界、多至 500 个展示点、truncated、来源。坐标为 AppSample 游戏投影，不是地球经纬度。边界与点坐标保持同一投影。

地图消息独立于角色/武器/圣遗物卡片：新增 SSE `maps` 事件，完成事件的 `maps` 与 `mapSnapshotId` 支持最终保存；历史 Message.maps 与 Conversation.mapSnapshotId 保持兼容旧数据。仅接受经验证服务端查询生成的卡片；忽略畸形/未来协议，不执行模型生成的 HTML 或任意资源地址。

## 查询

工具 `search_map_regions(query,country?)` 搜索地区层级并显式返回歧义；`query_map_resources(region,resource,country?)` 对固定地图快照执行查询并返回限定范围、数量、审核状态与来源。工具使用实际目录名称/ID，资源支持源名称/ID。地图问题不应因文献检索为空而提前结束；模型只能据工具结果回答数量。混合问题仍可调用文献工具。

保留原有空间规则：父区 XZ 约束、多块围栏、已知 Y 高度、边缘不确定性和同级区域重叠。没有边界、未校准场景、歧义区域/资源、快照不存在、附近未定义等情形返回明确错误，不转成零。地图快照固定在单次研究与对话历史，加载旧快照失败不悄悄换成当前版本。

## 数据与地图

将已核验 bundle 和瓦片/图标准备到 git-ignored `data/maps`，生成含哈希的不可变快照目录及当前 manifest。部署可用 `MAP_DATA_DIR` 只读挂载。资源 API 只读取已知快照的允许文件；高清补片只允许服务端拼接固定 AppSample 官方源地址，拒绝穿越和任意 URL。

React Canvas 卡片支持适应容器、平移、缩放、低缩放聚合、点选及来源链接。默认显示实际底图，不以空白底代替；地图缺片/资源不可达时有明确状态。大范围结果展示有上限但 count 始终是完整匹配数，并明确展示截断。显示地图版本及复核状态，禁止把 requires-review / projected-snapshot 当成全部精确三维核验。旧的主站页面样式、文本卡片与引用行为保留。

## 验收

- 真实快照：奥摩斯港草神瞳 2 个，33876/33877，非凭文献或模型猜数。
- 缺围栏、重名、独立场景、边缘点/高度、旧地图快照等均不误导。
- 真 Agent 执行循环可调用两个地图工具，地图问题不依赖文献命中，发送结构化地图事件与最终消息。
- 浏览器实际提问链路展示 Canvas、标点与边界，刷新历史恢复、独立快照固定、无外部任意 URL/HTML，桌面/手机、深色、拖动缩放与标点点击。
- 类型检查、Web 单测、生产构建与相关 E2E，必要真实模型连通性取决于已有本地凭据，不能把固定模型返回的链路测试称为真实模型验证。
